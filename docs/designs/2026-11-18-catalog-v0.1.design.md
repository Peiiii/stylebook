# UI Atlas · 首版功能与界面设计

状态：用户于2026-11-18确认按本方案开发首版，并授权公开仓库与独立开发会话；产品界面尚未实现。

目标沿[产品目标与已确认结论](../product-brief.md)。推荐主链路：**浏览参考 → 同条件对比 → 选定整套或局部方案 → 分享视觉依据与采用说明 → 查看或复用代码**。

## 1. 首版范围

| 能力 | 首版具体行为 |
| --- | --- |
| 浏览与发现 | 三个入口：风格、组件、场景；以真实预览缩略图为主，支持名称/ID/标签搜索与按用途筛选 |
| 条目详情 | 大面积可操作预览、稳定ID、适用/不适用说明；浅深色、视口和适用状态可切换 |
| 并排比较 | 默认两项；小型组件最多三项；同一比较组使用一致内容、视口及状态 |
| 截图与分享 | 干净预览模式隐藏目录工具，提供专用链接，方便浏览器截图；复制链接保留选项 |
| 采用说明 | 确定整体风格及局部条目后，复制一段Markdown，包含ID、参考链接、关键约束与代码位置 |
| 代码使用 | 展示实际样例源码、必要依赖与用法，可复制；不把代码展示当唯一使用方式 |

首版不提供账号、云端收藏、收费、社区上传、AI自动评判、安装CLI或自建包管理。暂不承诺“下载PNG”或“复制图片”；先提供截图友好预览，后续单独验证字体、跨域资源和复杂效果后再加入自动导出。

本地原型地址只能本机使用。公开分享在有真实部署后才成立，目录内没有部署地址时不会假装生成公网链接。

## 2. 信息模型

所有内容统一作为“条目”，用类型区分用途；不为三种入口建立三个管理系统。

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定英文点号ID，例如 `theme.soft-elevation`、`card.elevated`、`page.settings.sections` |
| `title / kind` | 人类可读名称；kind为风格、组件、场景 |
| `tags / summary` | 用途、关键特征、适用及不适用说明；搜索不依赖用户知道精确术语 |
| `comparisonGroup` | 可比较对象的组，例如card、search、page.settings；不同对象不强行同屏对比 |
| `preview` | 真实预览入口、支持的视口/浅深色/状态、测试内容集及预览图 |
| `source` | 实际实现位置、依赖、来源与许可说明；外部参考与可分发代码清楚区分 |

风格条目以完整场景展示自己的排版和表面系统，并链接对应组件/场景条目。组件和场景可以标记适配哪些风格；不要求所有现有或未来样例都接受同一套CSS变量。

用户选型由“一个整体风格 + 可选的局部条目”组成。例如整体采用 `theme.soft-elevation`，卡片采用 `card.elevated`，设置页采用 `page.settings.sections`。首版不要求用户填写版本号；不可把同一ID悄悄换给不相关对象。

## 3. 页面与布局

### 目录浏览

顶部为品牌、三个入口和搜索；搜索框有默认可见边界。下方是用途筛选与预览网格，不放大幅营销头图和无关统计卡。

桌面建议三列、平板两列、手机一列，按实际预览宽度收敛。每项预览、名称、少量特征、稳定ID与加入比较入口组成一个完整卡片；预览框内外的背景明确分开，不把样例风格与目录外壳混在一起。

筛选无结果时显示保留的筛选条件和清除入口。比较选择区只在选中条目后出现，不长期占据阅读空间。

### 条目详情

顶部一行：返回目录、名称、ID复制、加入比较、采用。下方“预览 / 说明 / 代码”切换，默认预览。

预览占据主要区域，工具栏只保留当前支持的视口、浅深色与样例状态。说明和代码不会常驻挤压画面；长代码有高亮、复制与依赖提示。

缩略图只用于识别风格；详情支持真实尺寸查看与明确标注比例的适配窗口模式。不会把缩小到难以阅读的复杂页面当作完整预览。切换页签、查看源码和返回目录时保留合理的选型及浏览上下文。

### 比较

顶部共享比较条件；每列保留条目名称、ID、移除和放大入口，下方放预览。风格使用同一完整页面内容比较，组件使用同一测试内容比较。

整页默认两项，小型组件最多三项。窄屏允许在保留比较条件的情况下切换A/B，不把三列硬压到手机屏幕。大页面适配显示时明确缩放比例，可随时打开单项真实尺寸。

不兼容的比较组给出原因并保留已有选择；没有某个状态的示例显示“不适用”，不静默换到另一个状态造成假对比。

### 采用与截图

“采用”在用户主动操作后打开简短选型面板，列出整体与局部选择，可移除或替换；主动作是复制采用说明，无需注册。

“干净预览”打开只包含样例的专用页面，去掉目录导航和调试说明；截图可以直接交给AI。来源、ID和说明在条目页与复制文本中保留，避免截图离开网站后无法追溯。

## 4. 首批内容与视觉方向

目录外壳：中性、克制但有明确视觉分区；搜索和工具可识别，预览内容获得最大空间。外壳与样例的浅深色分开，不让切换外壳主题意外改变比较条件。

两套风格用同一份通用任务工作台内容对比：

| 风格 | 视觉特点 | 展示重点 |
| --- | --- | --- |
| `theme.clean-outline` | 紧凑、清晰边界、少阴影、稳定行结构 | 适合扫描、定位和工具操作的组织方式 |
| `theme.soft-elevation` | 柔和底面、白色容器、轻阴影、舒展但有分组的间距 | 独立信息对象、阅读与设置场景的层次 |

它们是首批可比较样例，不是产品永久限定的两种风格。

六组组件样式：卡片、搜索/筛选、状态图标与分类标签、菜单、抽屉、页签。按需要提供少量明显不同的变体，不靠换颜色增加数量。

两个完整场景：**汇报/活动流**、**定义阅读与策略设置**。后者必须包含正常Markdown排版、长段落、代码块、空字段和成组参数，防止只优化首页或其中一个页签。

所有样例使用通用演示内容，不放私人运营数据、账号标识或会话ID。不伪造真实客户、业务成果或用户评价。

## 5. 技术与维护方案

推荐React + TypeScript + Vite；目录外壳复用shadcn/Radix风格的可组合基础组件与Tailwind，样例保持自身风格边界。本轮不安装产品依赖，具体锁版本在方案确认后的脚手架批次记录。

理由：需要搜索、对比、状态预览和复制交互，但首版没有必须服务端执行的用户链路。Vite支持开发服务器和静态资产构建；可以先部署为静态网站。[Vite官方说明](https://vite.dev/guide/)

最强替代是Storybook：擅长组件状态和开发者预览，但本产品首先服务普通人的风格发现、比较和沟通，需要自己的信息架构。首版不同时维护两套目录壳；未来需要独立的组件开发工作台时再评估接入。[Storybook的story与状态模型](https://storybook.js.org/docs/get-started/whats-a-story/)

条目在Git中以模块文件维护，预览直接运行这些实现。完整页面和可能影响全局样式的例子使用隔离预览；目录不执行用户上传或远端任意代码。先使用自有、已审阅样例，不建设通用插件运行时。

当前无需数据库、服务端、登录、付费服务或AI API。查询与选择状态用URL保存，必要的临时偏好保存在浏览器本地；分享只依赖URL中可表达的条目与状态，不依赖发送者的本地收藏。

静态路由优先采用hash路由，条目/比较/预览都有独立入口，避免依赖部署端重写规则。发布后可按真实宿主调整，不将未发布的localhost地址作为他人可访问的链接。

代码采用先做复制与清楚的依赖说明；后续标准化分发优先评估既有registry协议，不另造安装生态。[shadcn registry](https://ui.shadcn.com/docs/registry)

建议目录（待实现，不是已经存在的产品文件）：

```text
src/catalog/       条目元信息与索引，负责发现和检索
src/examples/      组件与完整场景的实际实现、测试内容
src/preview/       隔离承载、视口与状态控制
src/pages/         浏览、详情、比较、采用、干净预览
src/components/    目录外壳的共享控件
docs/             产品目标、设计与验证记录
```

## 6. 验收链路

| 链路 | 操作与系统响应 | 成功判定 |
| --- | --- | --- |
| 普通人选型并与AI沟通 | 从目录找到两套风格→用同样内容比较→选择一套→复制采用说明→打开干净预览截图 | 说明含稳定ID、明确特征和可追溯位置；不懂代码也能完成；公开部署后用新浏览器打开链接仍恢复同一选择 |
| 开发者复用 | 从条目预览切换到源码→获得代码与依赖→在隔离目标页采用→检查默认与关键状态 | 预览和复制代码来自同一实现；依赖完整；不能把无法单独使用的一段截图示意当可复用组件 |
| 长内容与跨页面一致性 | 打开完整设置场景→查看Markdown、空字段、策略分组→切换浅深色及窄屏→返回目录 | 没有裸文字铺底、原始Markdown标记泄漏、内容裁切、控件丢失；同风格在不同场景一致 |

还需覆盖无搜索结果、无效条目ID、预览加载失败、复制失败和不兼容比较。失败说明原因并保留已有选择；预览失败不伪装空白页面，剪贴板受限时提供可手动选择的文本。

审美偏好由用户对完整场景作选择；不以自动检查通过或自评99分替代认可。开发验证时分别记录真实交互、视觉截图、对比公平性和代码可复用性。

## 7. 分步落地与当前检查点

1. **已做**：建立独立项目、接入开发体系、记录产品目标与方案；用户已确认进入首版开发。
2. **第一批**：搭建目录壳与一个卡片条目，打通浏览→预览→对比→复制采用说明，并验证预览/代码共源。
3. **第二批**：补两套风格、六组组件、两个完整场景及适用状态；检查所有场景，不只看汇报页。
4. **发布批次**：按明确的仓库与发布授权设置远端、发布站点，再验证外部访问与分享。

用户已确认长期目标、独立项目和首版开发方向；实现按本方案推进，具体技术版本与可行性证据在开发批次补齐。产品代码、运行页面、依赖可行性与业务验收目前均未完成，不用文档检查冒充实现验证。
