# Stylebook · 产品目标

Stylebook 是基于 shadcn/ui 的精选多风格组件库。2026-11-18 用户确认直接复用 shadcn/ui 源码及交互设计，投入集中在可扩展的风格体系和实用页面模板。

## 当前交付

- 直接复用 shadcn/ui 的文档阅读布局、侧栏、主导航和组件预览中相关的代码。按本地 React/Vite 环境适配数据及路由，不展示源码示例。
- 官方 New York Radix 组件及示例 39 项，覆盖常用表单、导航、弹层、反馈和数据展示。
- 规范组件名保留英文；演示操作、说明、表单、日历、无障碍文字与模板数据面向中文用户，默认简体中文。
- 官方 Blocks 采用 Login、Collapsible Sidebar、Dashboard，包含实际预览。
- shadcn Default、Material、iOS与复古共用原有组件接口，39 个组件支持单页紧凑总览。目录包装与主题组件样式分离，Material 使用中性表面和蓝色强调。早期版本历史由 Git 保留。
- 后续按真实场景扩展风格或组件，更新时核对固定上游提交及已移植片段。

## 长期目标

成为面向所有人的通用UI风格选型目录：当人们不知道选什么风格，或不满意AI生成的界面时，可以找到清晰的视觉参考，用截图、链接、名称或采用说明与AI和设计开发人员沟通；也可以直接查看、参考和复用对应组件代码。

核心价值是把“简约一点”“不要这么丑”等抽象偏好，转成大家能共同指认、比较和执行的视觉选择。产品不限定AI组织、后台管理或某个组件框架；未来可覆盖网站、应用、内容阅读、工具和其他界面场景。工作名暂为UI Atlas，不代表品牌已确定。

## 服务谁、解决什么问题

| 使用者 | 主要需求 | 得到的结果 |
| --- | --- | --- |
| 不写代码的用户、产品负责人 | 看效果、选风格，准确表达想要什么 | 截图友好预览、可分享链接、稳定名称与ID、采用说明 |
| 与AI协作的人 | 让AI理解并持续遵循明确参考 | 整套风格与局部选择的组合，具体视觉约束和来源 |
| 设计师、开发者 | 比较合适的实现方式，降低落地成本 | 可操作样例、场景取舍、代码与依赖说明 |

不要求用户懂组件名称、CSS或安装命令才能完成选型。代码复用是增强路径，视觉选择和沟通本身就必须有价值。

## 已确认的设计结论

- 建为独立探索项目；按探索目录统一工具接入开发体系。
- 目录提供整套风格、组件样式和场景组合。基础按钮目录不足以验证一整页是否好用。
- 风格包含排版、空间、表面、圆角、边框、阴影、颜色和交互状态，不能退化成换色器。
- 同一场景用相同内容、相同状态和相同视口比较，避免因素材差异做出错误选择。
- 条目具有稳定英文ID，支持直接指定；实际预览尽量与可复用代码共源。
- 简约是减少识别和理解的工作；密集信息需要充分分区，卡片、背景、标签和阴影都有具体用途。
- 常见状态优先用固定语义图标；难理解、数量过多或需要解释原因时补必要文字，始终保留可访问名称。
- 参考必须包含长内容、空内容、异常和窄屏等适用条件，不能只展示一个漂亮的理想状态。
- 已有全局clear-ui负责规则判断；本项目提供可视参考和可复用实现，不复制出第二套规则正文。

这些结论来自2026-11-17至18日的讨论。原工作台只是问题发现与首批场景的来源，不构成本产品的领域限制，不导入其私人账号或运营数据。

## 产品价值如何判断

先验证一个小而完整的链路：用户找到合适参考，能解释为什么选它；将参考交给AI或开发者后，对方可以辨认对象、获得实现依据并落地到目标页面。

首版关注可观察的结果：能否发现风格差别、完成同条件比较、生成可用的采用说明、找到对应代码。长期再通过真实用户观察选型耗时、沟通返工和参考复用情况；不预先编造提升比例，不以收录数量代替质量。

## 演进方向

首版建立精选样例与可靠选型体验；随后扩展更多用途与明显不同的风格、完整场景和组件生态；有真实需求再增加自动截图导出、标准化安装、社区贡献与智能推荐。

“成为大全”是持续积累且可检索、可比较、可采用的长期方向，不要求第一版穷举所有风格。首版功能与界面建议见[设计方案](designs/2026-11-18-catalog-v0.1.design.md)。
